## Artifacts (A-rpm)

The `rhel-coreos` image in the same release payload has no commit info and must be drilled down at the RPM/SRPM level — positioned as part of Phase A (see [operations.md](operations.md) for details). `/mnt/hdd/casket-ocp/casket-20260529-ocp-srpms.sqfs.xz` — **3.5 GB** (mounted at `/srv/sources-ocp-srpms`)

**All binary RPM sources from 7 OCP versions (4.14.58-4.20.22) consolidated into one file** from the `rhel-coreos` image. 843 deduplicated SRPMs, coverage 1390 / 1392 = **99.86%** (the 2 uncollected are `redhat-release-9.2-0.15.el9` and its eula counterpart, already removed from Red Hat repos).

Each SRPM is **extracted** (`srpms/<NEVR>/` with spec + upstream source tree + `patches/`, same layout as Phase A/B). The `.src.rpm` files themselves are not included (this is for source browsing, not rpmbuild). Extracted layout + xz recompression dedup: 8.5G → **3.5G** (rebuilt 2026-05-28). Since `srpms/` is deduped across all versions, `by-ocp/<ver>/` symlink trees make per-version origin visible (added 2026-05-29).

```
squashfs-root/
├── srpms/                       843 SRPMs (extracted, deduplicated)
│   └── systemd-252-51.el9_6.4/
│       ├── systemd.spec         spec (top level)
│       ├── systemd-252/         upstream source tree (from Source* tarball extraction)
│       └── patches/             .patch files + non-tarball auxiliary sources
├── by-ocp/<OCP-VER>/<src-name>  → ../../srpms/<NEVR> symlinks (341-368 per version)
│   └── 4.20.22/systemd          → ../../srpms/systemd-252-51.el9_6.4
└── meta/
    ├── MANIFEST.json            SRPM index + binary RPM list per OCP version
    ├── bin-to-src.tsv           binary-NEVRA TAB source-NEVR TAB ocp-version (3844 rows)
    ├── README.txt
    ├── rpmdb/<V>.tsv            rhel-coreos rpmdb for 7 versions (name TAB epoch TAB ver TAB rel TAB arch)
    ├── wishlist.txt             1392 unique (name-ver-rel) request list
    ├── missing.txt              unresolved after initial fetch
    ├── missing3.txt             final unresolved (2 items)
    └── fetch*.log               dnf download --source logs
```

Browse SRPMs for a specific release with `cd /srv/sources-ocp-srpms/by-ocp/4.20.22/`. Old `casket-20260524` (bundled 8.5G) / `casket-20260528` (without by-ocp) retained for rollback.

**Phase B v2 improvements (completed 2026-05-27)**: v1 only fetched 1-6 github sources per minor, but v2 added source URL recovery from CSV metadata (`annotations.repository`, `spec.links[]`) and tag/branch fallback (v-prefix normalization, `release-X.Y` / `main` / `master`), improving to 27-86 per minor (278 tarballs / 4.6 GB total). Remaining unfetched are operators whose CSV repository field points to `access.redhat.com/containers/...` or `www.redhat.com` (50-60 per minor) — a structural limitation as they don't point to github.

> **Resolution overhaul (2026-06-09, completed)**: The table above shows old rollout values (2026-05-27, 27-86 github fetches) and not current production values. Three independent bugs suppressing resolution were fixed, increasing **4.18 from 34 → 110 unique source dirs** (verified).
> 1. `phase-b-fetch-bundles.sh`: Was dropping operators without a `containerImage` annotation in CSV from `containers.tsv` (excluding 30/122 including serverless/pipelines/compliance).
> 2. `phase-b-resolve-v2.sh`: Added per-repo ref strategies (gitops `v<MAJ.MIN>.0` / maistra `maistra-<ver>-dev` / serverless `release-<product-minor>` / compliance branch) and fixed the empty-ref column shift (`IFS=$'\t' read` collapses consecutive tabs) with a `_NONE_` sentinel.
> 3. `phase-b-package.sh`: meta/MANIFEST/INDEX now prefer `git-v2.tsv`.
>
> Pure logic extracted to `scripts/lib-resolve.sh` with regression tests in `tests/` (run in CI). Details in [phase-b-uncollected-plan.md](archive/phase-b-uncollected-plan.md). Two remaining hard cases need version mapping: pipelines (product v1.22 ↔ tektoncd v0.79) and compliance (Red Hat is ahead of public tags).

Contents of each artifact:

```
squashfs-root/
├── catalog/<operator>/catalog.json    File-Based Catalog (FBC) verbatim
│                                      (from registry.redhat.io/redhat/redhat-operator-index:v<minor>)
├── bundles/<operator>/<head>/
│   ├── manifests/                     CSV + CRDs (OLM payload)
│   └── metadata/                      bundle annotations.yaml
├── git/<name>-<short_sha>/             github source (extracted; combined v1 labels + v2 CSV/branch fallback)
└── meta/
    ├── MANIFEST.json                  full operator/container/git info
    ├── operators.tsv                  name TAB channel TAB head_bundle TAB head_image
    ├── containers.tsv                 name TAB head_bundle TAB containerImage TAB csv_version
    ├── labels.tsv                     containerImage TAB source_url TAB vcs_ref
    ├── git.tsv                        name TAB source_url TAB vcs_ref TAB tarball (or NO_SOURCE)
    ├── git-v2.tsv                     v2 rescues: CSV repo + smart fallback strategy

```

Size variation across minors is due to older minors' FBC catalogs (4.14-4.16) containing ~100 MB of long upgrade history for ansible-automation-platform and similar.

**Operators v2 still cannot fetch**: Operators whose CSV/label repository field points outside github (`access.redhat.com/containers/<...>`, `www.redhat.com`) cannot be fetched even with v2. These are mostly Red Hat internal brew/cachito builds not tied to public git tags, making reproducible github source retrieval structurally impossible. 50-60 remain per minor.

## Artifacts (B-operand)

A sub-phase looking one level deeper into the same operator catalog as Phase B (details in [operations.md](operations.md)).
`/mnt/hdd/casket-ocp/casket-<date>-layered-ocp<minor>.sqfs.xz` — **1 integrated casket per minor** (all 9 minors 4.14-4.22, **0.8-1.1 GB** each). Mounted at `/srv/sources-layered-ocp<minor>/{cnv,acs,mce,acm,rhoai,odf,quay}/`, with `bundle/`, `git/`, and `meta/` under each product.

Where Phase B collects the **operator control image** source, B-operand collects the upstream github source for each layered product's **operand images** (CSV `spec.relatedImages`). 7 target products:

| Product | Package | License |
|---------|---------|---------|
| CNV (OpenShift Virtualization) | `kubevirt-hyperconverged` | Included with OCP |
| MCE (Multicluster Engine) | `multicluster-engine` | Included with OCP |
| ACS (Advanced Cluster Security) | `rhacs-operator` | Platform Plus |
| ACM (Advanced Cluster Management) | `advanced-cluster-management` | Platform Plus |
| RHOAI (OpenShift AI) | `rhods-operator` | Separate purchase |
| ODF (OpenShift Data Foundation) | `odf-operator` | Platform Plus |
| Quay | `quay-operator` | Platform Plus |

Source resolution: `phase-b-operand-resolve-labels.py` resolves each operand image by trying **`upstream-vcs-url` → `component-map` → `oci-source` → `source-location` → `url`** in order for github URL + ref (ODF/Quay use `COMPONENT_MAP` as fallback since their public git only has umbrella/main). Resolution counts (operands resolved / total) example: 4.18 — cnv 54/59, mce 38/39, acs 12/12, acm 50/64, rhoai 89/100, odf 3/3, quay 1/10. Download failures common across all minors: `openshift/*` and `rh-openjdk` (already collected in Phase A, avoided to prevent duplication). Quay has only umbrella git publicly (1/10). ACM 4.14/4.16 have lower resolution due to label format differences (needs further investigation). Details in [phase-b-operand-plan.md](archive/phase-b-operand-plan.md).

```
squashfs-root/                         (casket-<date>-layered-ocp<minor>)
├── cnv/
│   ├── git/<name>-<ref>/              operand upstream source (extracted)
│   │   └── by-component/ by-repo/ INDEX.tsv   reverse-lookup index
│   ├── bundle/                        head bundle manifests/metadata
│   └── meta/                          MANIFEST.json, images.tsv, git.tsv
├── acs/ mce/ acm/ rhoai/ odf/ quay/   same structure
└── README.txt
```

The problem of dedup directory names hiding the actual repo (e.g. kubevirt core aggregated under an unrelated name) is addressed by each product's `by-component/`, `by-repo/`, and `INDEX.tsv` (same `build-source-index.py` as Phase A/B). Old per-product 4.20 caskets moved to `/mnt/hdd/casket-ocp-test/superseded-perproduct-20260603/`.
