# Usage modes and new host setup

The casket `.sqfs.xz` files are **not distributed as standalone files**. There are two usage modes:

| Mode | Requirements | Section |
|------|-------------|---------|
| (A) Use a running host's services over the LAN (recommended — most people) | Browser / MCP client only | 1 |
| (B) Build everything on your own host | Linux host + **valid Red Hat subscription** | 2-5 |

## 1. (A) Using a running host's services

No setup required. Just connect to the two entry points provided by the casket host:

- **OpenGrok Web UI** — `http://<casket-host>:8080/`. Browser-based symbol search, cross references, and source browsing (see [../opengrok/README.md](../opengrok/README.md) for project list and layout)
- **casket-mcp** — Search and read sources from Claude or any other MCP client. LAN connection instructions (HTTP transport URL, connection examples) are in [../mcp/README.md](../mcp/README.md)

Both are read-only. The actual source data lives on the host at `/srv/sources-*`; nothing is copied to your machine.

## 2. (B) Building on your own host — pre-flight check

```bash
./scripts/casket-doctor.sh --build   # shows OK/WARN/FAIL for tools, registry auth, and disk space
```

If you get stuck during the following steps, re-run this first and address FAIL/WARN lines.

## 3. Storage planning

Approximate capacity requirements (full configuration as of 2026-07):

| Item | Size | Notes |
|------|-----:|-------|
| Casket artifacts (all phases + catalogs) | ~45G | Generated by builds |
| Build intermediates | ~150G peak | Can be deleted after completion |
| OpenGrok index (optional) | ~150-250G (default) / ~900G full | Only needed for Web UI search. Without it, casket-mcp/ripgrep still work. Default indexes only the minors in `config/opengrok-minors.txt` (latest 3-4 minors) |

SSD/HDD split is flexible (the reference host uses "SSD = build work + OpenGrok index / HDD = artifacts", but this is a sizing decision, not a requirement). Indexing all minors requires ~900G, so the default indexes a subset on SSD. Environment variables for changing locations: `CASKET_WORK` (work root, default = this repo's checkout location), `CASKET_OUT` (artifacts, default `/mnt/hdd/casket-ocp`), OpenGrok index uses `DATA_VOLUME=<path>`.

## 4. Build and mount

**Hard prerequisite: valid Red Hat subscription.** Obtaining a pull secret (console.redhat.com), pulling operator catalogs from `registry.redhat.io`, registering the RHEL 9 VM for A-rpm, and fetching EUS SRPMs — all depend on this. Without a subscription, only Phase A's GitHub fetching works.

- Tool requirements: `oc jq curl awk sha256sum mksquashfs xz rpm2cpio cpio` + a pull secret with auth for both quay.io and registry.redhat.io (`~/.docker/config.json`, overridable with `AUTHFILE`)
- A-rpm specifically requires a subscription-registered RHEL 9 VM ([pipeline.md](pipeline.md))
- The build-to-production flow is check → build → swap → cleanup in [operations.md](operations.md). After swap, mounts are automatic; for persistence across reboots, run `sudo ./scripts/install-mounts-service.sh` (one-time)

To add caskets outside registry management (e.g. separate RHEL caskets), add `file TAB mountpoint` lines to `config/static-mounts.tsv` and run `sudo ./scripts/casket-mounts.sh --apply` (see the "Mount management" section in [operations.md](operations.md)).

## 5. Search infrastructure (optional)

- **casket-mcp** ([../mcp/README.md](../mcp/README.md)): Works with just the mounts, no indexing needed. Recommended to try this first to see if it's sufficient
- **OpenGrok** ([../opengrok/README.md](../opengrok/README.md)): Use if you need symbol search and cross-references. Costs ~800G of index and several hours for initial indexing
